# Security

Threat model and security model for Ting, mapped to the OWASP Top 10:2025.
Current as of 2026-10-20. Norwegian user-facing text about the same topics is
in `PERSONVERN.md`.

## What Ting is

Ting is a static web app. It has no server, no account, and two kinds of
network calls to other origins after the page has loaded: one image request
per start sends the path `/ting/` to GoatCounter (`src/lib/visitCount.ts`),
and an ISBN scanned or typed for a thing in a book category sends its
thirteen digits to a public catalogue (`src/lib/lookup.ts`). Turning on receipt
reading downloads the OCR models from the app's own origin.

Everything the user registers lives in the browser's IndexedDB on the device,
optionally mirrored to a folder on disk, to downloaded copies, and to the
user's other devices as a sealed file through the share sheet (AirDrop). All
of it is encrypted with a key derived from a passphrase the user chooses, or until then from a random secret sealed on the device.

That shape removes whole classes of risk (server-side access control, session
tokens, API abuse) and concentrates the rest in three places: the device, the
files the app writes, and the code that ships to the browser.

## Assets

| Asset | Where it is | Protection |
|---|---|---|
| Items, properties, field settings, tombstones, photos | IndexedDB, `ting.json` and `bilder/` in the folder, downloaded copies | AES-256-GCM under a random data key (DEK) |
| The DEK | Memory while unlocked; wrapped in the `vault` setting and in every file | Wrapped with a key derived from the passphrase (Argon2id) |
| The register's secret, until a passphrase | Sealed in the `recoveryCode` setting; never shown, never in a file or the folder | 100 bits from `crypto.getRandomValues`, stretched like a passphrase; deleted when the user chooses a passphrase or the vault is taken over from a file. A file sealed with a 1.16 code, which was shown, still opens with it |
| The passphrase | Component state while a form is open, never stored | Argon2id, 64 MiB, 3 passes, 1 lane, 16-byte salt, NFKC-normalised input |
| The DEK, device copy (on by default) | The `deviceKey` setting on that one device; never in a file or the folder | Wrapped with a non-extractable AES-GCM `CryptoKey` the browser keeps beside the data (`lib/deviceKey.ts`) |
| The passkey record (only where «Husk passord» is off and the device has Face ID or Touch ID) | The `passkey` setting on that one device; never in a file or the folder | Credential id and public key only: it opens nothing. It guards the device copy above, which stays while it exists (`lib/passkey.ts`) |
| CSV and print output | Wherever the user puts them | None: they exist to be read. The app says so |

In the clear: row ids, the photo MIME type, sync times and switches (`clock`,
`fieldsChangedAt`, `lastMergedAt`, `receiptReading`, `rememberDevice`, `passkeyOffered`), the passkey user id (`passkeyUser`), a random
device id, the folder handle, the wrapped key with its salt and parameters, the passkey
record (credential id, public key, key id), and the
`exportedAt` on the outside of a file envelope. None of these reveal content.

## Threat model

| Actor | Can | Cannot |
|---|---|---|
| Someone with the unlocked device | See and change everything, like the user: the device copy opens the app without a question, or behind Face ID | Open a copy or the folder, or the app on another device, without the passphrase |
| Someone who can run code in the browser profile or on the elzacka.github.io origin (DevTools on the unlocked device, an extension, another app on the origin) | Unwrap the device copy and read the DEK itself, while a device copy exists («Husk passord» on, or Face ID): every device shares that DEK and a passphrase change keeps it, so every copy and the folder open with it, later ones too | Anything on a device where «Husk passord» is off and Face ID is not set up: no device copy exists there |
| Someone who can pass the device's own lock (Face ID, Touch ID, Windows Hello, the screen lock or its code), or the password manager's unlock where the passkey or the passphrase is saved there, where «Husk passord» is off | Open the app, like the user | Open a copy or the folder, or the app on another device: the device copy stays on this one |
| Someone with the locked device, the folder or a copy | Read ids, counts and timestamps; attempt an offline guess of the passphrase, paying the Argon2id cost per guess | Read content, forge a document (GCM tag), roll back data with an old copy: a merge weighs the stamps inside the sealed document, field by field, so an older copy never replaces newer data |
| A crafted `ting.json` or folder | Be rejected by the schema | Reference files outside `bilder/<uuid>-<n>.bin` (or the older `<uuid>.<ext>`), inject markup, ask for unbounded key-derivation memory |
| Someone who receives a sync file by mistake (a wrong AirDrop target) | Read ids and counts, as with any copy | Read content, or change the owner's passphrase by swapping the clear-text vault: only the vault copy inside the sealed part is ever adopted (`lib/sync.ts`) |
| Someone who hands the user a crafted file to fetch | Be refused: Importer til registeret merges only a file sealed under the user's own key, or one whose passphrase the user types | Delete or overwrite things through a plain (unsealed) file's tombstones or stamps: a plain file can only replace, and only after the user confirms the count when the register holds things |
| A page that frames the app | Load it | Show it: the app refuses to render inside a frame |
| A compromised dependency or CI action | Ship malicious code to every user | Nothing stops this except the controls under A03 below; it is the largest residual risk |
| The hosting provider (GitHub Pages) | Serve altered files, omit headers | Read user data: none is ever sent |
| A lookup catalogue (Nasjonalbiblioteket, Open Library) | See the digits of an ISBN and the IP address, only when the user scans or types an ISBN in a book category that the register does not already hold; answer with a hostile title, author, year or language | Learn anything else: no cookies, no referrer, no other field. Inject anything: the answer is Zod-validated, each text bounded to 200 printable characters, the year to four digits and the language to a name `Intl.DisplayNames` gives a two- or three-letter code; it is rendered as text and fills only Navn and the register's own Forfatter, Utgitt and Språk for the user to review before Lagre |

Out of scope: a compromised browser or operating system, malware on the device,
and an attacker who can watch the user type. No web app can defend against
those.

Deliberate choices that shape the model:

| Choice                                                                                                     | Consequence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No recovery path | A forgotten passphrase means backups, files and the folder cannot be opened; a device that remembers the register still opens it there. Without a passphrase, export, the folder and «Husk passord» off ask for one first: a copy sealed with the device's secret opens nowhere else, and a lock with no passphrase behind it could not be opened |
| No server, no telemetry                                                                                    | Nothing to breach centrally; also nothing to alert on                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Receipt OCR on the device, opt-in, no generative model (elzacka, 3 October 2026) | A receipt photo and its text never leave the device; the models (PP-OCRv6, recognition only) are same-origin, downloaded only when the switch goes on and deleted when it goes off. Recognised text is untrusted input: parsed by rule into a name, a price, a date and a store, shown in editable fields, stored only after Lagre; the raw text is discarded |
| Lookup only for an ISBN in a book category, as soon as the field holds one (elzacka, 9 October 2026); barcode decoding stays on the device | Outside a book category a scan reveals nothing. In one, scanning or typing the book's ISBN is the choice: that one code goes to one catalogue, or to the second when the first has no record, and the line under the field names the source |
| The device opens the app without a question by default; the passphrase is optional, chosen in Innstillinger (elzacka, 2026-10-20) | A question at the first start or at every start is a cost that keeps people from using the app at all. The first start seals the vault with a random secret kept sealed on the device; a non-extractable device key opens it there. The user can turn remembering off, and Face ID, where on, asks instead. The lock button and idle lock show only where something asks again, since otherwise they would lock nothing |
| Face ID or Touch ID as an app lock wherever «Husk passord» is off and the device has a platform authenticator, set up without a separate choice (elzacka, 2026-10-20) | A phone closes the app on its own, and a passphrase typed at every start is a cost. The passkey is made on the platform authenticator with user verification required. At the lock screen the app checks the assertion itself (`assertionValid`): its own fresh challenge, the origin, no cross-origin frame, the rpId hash, the user-present and user-verified flags, and the signature against the public key from creation (ES256 or RS256), then opens the device copy. It is a check in the page, not a key: code running on the origin opens the device copy without it, as it does with «Husk passord» on. PRF, which would tie the key to the passkey, is left out because providers give it unevenly (1Password, Chrome profile passkeys, iCloud Keychain in Chrome) and a lock that fails silently is worse. One user id per device, so a new passkey replaces the old one; a passkey no longer used is reported with `signalUnknownCredential` where the browser has it |
| The demo runs as a trial                                                                                    | A fresh data key lives in memory and everything is sealed under it as usual. Nothing wraps that key, so close or reload loses it. Nothing of the demo is the user's register                                                                                                                                                                    |
| A browser tab runs a demo; only the installed app opens the register (elzacka, 5 October 2026) | A tab uses its own database, `ting-demo`, refilled with examples under a throwaway key at every start, so it never reads, clears or adds to the register an installed app shares the origin's storage with. Adding and Innstillinger are not rendered there |
| Sync between own devices by file, merged per field (elzacka, 3 October 2026) | No server and no cloud: AirDrop carries the sealed file device to device. Merging never deletes what the other side changed later, keeps deletes deleted with tombstones, and is idempotent, so an old or repeated file is harmless. A newer passphrase travels inside the seal and replaces the older one on the receiving device. A file from a newer app version is refused rather than read with fields dropped |
| Idle lock after ten minutes, paused while edits are unsaved                                                | A device left open re-locks, unless something is mid-edit; that exception was chosen over losing the edits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| No content indexes in IndexedDB                                                                            | Search decrypts and filters in memory; an index would leak content                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## OWASP Top 10:2025, category by category

| #   | Category                               | Applies how                                                      | Controls                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | -------------------------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A01 | Broken Access Control                  | No roles, no server. Access is the device plus the passphrase  | A device that remembers the register opens it without a question; a new device needs the passphrase; `lock()` zeroes the key; idle lock in `useAutoLock.ts` (10 minutes without pointer or key input, re-checked when the tab becomes visible); folder access through the browser's own permission prompt                                                                                                                                                                                                                                                                                |
| A02 | Security Misconfiguration              | Static hosting, so headers are what the host gives               | CSP `default-src 'self'`, `script-src 'self' 'wasm-unsafe-eval'` (the wasm clause compiles the bundled barcode reader and allows no script), `object-src 'none'`, `base-uri 'self'`, injected at build; no inline scripts; `connect-src` names the two lookup hosts (`lookupOrigins` in `vite.config.ts`) and nothing else, `img-src` adds only GoatCounter, and no other directive allows an external origin; `registerType: 'prompt'` for the service worker so an update is never silent. Limits: `frame-ancestors`, `X-Content-Type-Options` and `Permissions-Policy` are only honoured as HTTP headers, and GitHub Pages sets none. Chrome logs this. The `<meta>` tags stay as documentation; `main.tsx` refuses to render when framed (except on the dev server, for `dev.html`), which covers clickjacking without a header               |
| A03 | Software Supply Chain Failures         | Seven runtime dependencies (onnxruntime-web the newest, for receipt OCR, pinned exactly; zxing-wasm for barcodes; both wasm files bundled, never fetched from a CDN), two OCR model files in `public/models/`, one build pipeline | `package-lock.json` with `npm ci`; `npm audit --audit-level=high` in CI; GitHub Actions pinned to commit SHAs; Dependabot weekly for npm and actions; `permissions: contents: read` on both workflows; no CDN, fonts or icons from outside; each OCR model and its dictionary must match a SHA-256 pinned in `lib/ocr/models.ts`, checked on every fetch and cache read; `csp.test.ts` fails the build if `connect-src` or `img-src` grows, `fetch` appears outside `lookup.ts` and the OCR loader, a view is counted, or app code names another origin                                                                                                                                                                                                                                                            |
| A04 | Cryptographic Failures                 | All data at rest                                                 | WebCrypto AES-256-GCM with a fresh 12-byte IV per seal; Argon2id from `@noble/hashes`; random DEK per vault; a wrong passphrase surfaces only as a failed tag check; the DEK is zeroed on lock; a file sealed on another device is opened with the passphrase and its key adopted, so devices converge on one DEK; adoption reseals the rows and sealed settings and stores them with the vault in one transaction, so a failed import leaves rows and key in agreement; a passphrase change carries a `changedAt`, and the newer wrapping of the same DEK replaces the older one only from inside the sealed document. Known gap: no additional authenticated data binds a sealed row to its id, so someone with database write access could swap two sealed rows. Accepted: they already have the device |
| A05 | Injection                              | Everything typed, pasted, restored or read from a folder is data | React text nodes only; no `dangerouslySetInnerHTML`, `innerHTML`, `eval` or `new RegExp` from input; Zod on every document (`itemSchema`, `propertySchema`, `dataFileSchema`, `envelopeSchema`, unknown keys dropped); CSV cells starting with `=`, `+`, `-`, `@` or tab get an apostrophe; photos accepted only with image MIME types; folder photo names must be `<uuid>-<n>.bin` or the older `<uuid>.<ext>`; route ids are matched, never interpreted; localStorage values are validated; a category's chosen icon is stored as a pack id matched by `^[a-z0-9_]{1,64}$` and only ever looked up, and the pack's SVG files are read at build time for their viewBox and path data alone; links in text are rendered only for `http(s)://` addresses matched by a fixed pattern, as text, with `rel="noopener noreferrer"`, and other schemes stay plain text; a pasted spreadsheet block is split on tabs and newlines into cell strings and goes through the same validation as typed cells; the phone form and the in-place edits on a thing's page build their input with the same `inputFrom` and store through the same schema as the table; a decoded barcode is reduced to printable characters and 128 of them (`cleanCode`), a lookup answer to 200, and only an ISBN is sent, and only when its check digit is valid (ISBN-10 or ISBN-13) |
| A06 | Insecure Design                        | The design is the main control                                   | Local-only, encrypted by default, no account to phish, threat model written down here and in `CLAUDE.md`; every store boundary validates; minimum passphrase length 12                                                                                                                                                                                                                                                                                                  |
| A07 | Authentication Failures                | The passphrase once per device, a device key after that, and where «Husk passord» is off, Face ID or Touch ID in front of it | Passkey: platform authenticator only, user verification required, the assertion verified in the page against its public key, challenge, origin and flags, the record dropped when its key id no longer matches the vault's. Passphrase: Never stored or logged; Argon2id bounds offline guessing; no lockout counter because guessing happens offline against the file anyway; idle lock covers the abandoned-device case; the lock screen's field is open to password managers (`current-password`, username «Ting»). Inherent limit: JavaScript strings cannot be zeroed, so the passphrase lingers in memory until garbage collection |
| A08 | Software or Data Integrity Failures    | Code integrity comes from the pipeline, data integrity from GCM  | Every document and photo carries a GCM tag; merging a folder or a sync file weighs the per-field stamps inside the sealed document, so no clear-text value can force a rollback, and a sync file must be sealed; Workbox precache uses content hashes; pinned actions and lockfile as under A03. Files written before encryption are still accepted unauthenticated, by design, and sealed on the first unlock                                                                                                                |
| A09 | Security Logging and Alerting Failures | No telemetry by design, so "alerting" means telling the user     | Sync errors surface in the Lagringsmappe status on Innstillinger; restore and save failures show a message; the console gets only the error's name and message (`errorText`), never the object, which for a validation error would carry the content that failed; an unreadable row is skipped and named in the console rather than hiding the register                                                                                                                                                                     |
| A10 | Mishandling of Exceptional Conditions  | Corrupt files, hostile parameters, render errors, a slow or hostile catalogue | OCR runs in a worker with an image size cap (`ocr/limits.ts`) and a 180 s timeout, and a failed read becomes one message; a lookup has an 8 s timeout, `redirect: 'error'`, `credentials: 'omit'`, `referrerPolicy: 'no-referrer'` and `cache: 'no-store'`, and every failure becomes one of four messages; KDF parameters read from a file are bounded (`m` up to 256 MiB, `t` up to 10, `p` up to 4) before any derivation runs; one undecryptable row does not block the rest; an error boundary shows a message and a reload button instead of a blank page; wrong passphrase, bad JSON and schema failures are caught and shown                                                                                                                                                                              |

## Residual risks, in order

| Priority | Risk | Why it stays |
|---|---|---|
| P1 | Supply chain: a malicious dependency or action update | Pins, audit and Dependabot reduce the window; they do not close it. Review every dependency PR |
| P2 | Weak passphrase | Twelve characters is a floor, not strength. Argon2id makes each guess expensive, not impossible |
| P2 | The device opens without a question, or behind Face ID only | Anyone who can use the unlocked device reads the register; code in its browser profile or on the elzacka.github.io origin can take the DEK itself, which opens every copy and the folder, later ones too. «Husk passord» off on a device without Face ID deletes the device copy and closes this |
| P2 | With Face ID or Touch ID, the device's own lock is as good as the passphrase on that device | It comes with «Husk passord» off on a device that has it; the device's own lock is then the guard, as it is for a password manager that fills the passphrase. Copies and the folder still need the passphrase |
| P3 | Sealed-row swap by someone with database write access | Would need AAD on every seal; the attacker already has the device |
| P3 | Idle lock is paused while edits are unsaved | A device left open mid-edit stays open until the edit is saved or discarded |

## If a language model is ever added

Field content, file content and model output are all untrusted. Send content
to the model as delimited data with a fixed instruction, never concatenated
into the instruction. Model output only fills fields for the user to review; it
never triggers an action, a write, a navigation or a file operation. Nothing
leaves the device without an explicit, per-use choice by the user, and the
encrypted-at-rest promise in `BRUKERVEILEDNING.md` and `README.md` must be
revisited first.
